# Auditoría y corrección i18n — 2026-10-25

**Revalidación integral:** 2026-10-26.

## Alcance y fuentes de verdad

La auditoría cubrió la web estática, PWA, rutas `i18n/`, CV Data API,
Markdown localizado, generadores, scripts de sincronización móvil, Capacitor y
CI. El contenido profesional canónico continúa en `index.html`; el contrato
estructural de idiomas, vistas y secciones está en
`data/portfolio-i18n.json`. `sources/profile-readme/` permanece separado y no
se utiliza como contenido del sitio.

Antes de modificar archivos se creó el respaldo recuperable
`assets/backups/2026-10-25/i18n-overhaul-v1/`, con 105 archivos originales
(3.628.238 bytes). Los 154 PDF y las fuentes del perfil público no fueron
sobrescritos.

## Divergencias encontradas y resolución

| Área | Divergencia | Resolución |
| --- | --- | --- |
| Rutas de idioma | Dieciséis idiomas abrían páginas distintas basadas en el README del perfil | Las 22 rutas conservan el locale y entregan la misma SPA canónica |
| Persistencia | El cambio de idioma podía abandonar la SPA o perder estado móvil | Idioma, tema y vista se conservan en `localStorage` y en la URL |
| Fallback | No había fallback uniforme por clave | Cualquier clave ausente usa español sin cambiar el locale solicitado |
| Cobertura real | Traducciones inline incompletas dejaban fragmentos en español | Catálogo versionado con 933 textos y 36 atributos para cada uno de los 21 idiomas traducidos |
| Semántica HTML | `html.lang` y `dir` no acompañaban todos los cambios | Se actualizan en cada selección; árabe y persa usan RTL |
| Markdown/API | Su estructura provenía del README público | Se generan desde las 16 secciones reales de `index.html` y el contrato canónico |
| Vistas | Documentación y validadores aún describían tres vistas | Recruiter, Normal, Deep y Freelance forman parte del mismo contrato |
| PWA | Las rutas y el contrato i18n no estaban completos en caché | El service worker precarga rutas y contrato, y restaura navegaciones con query offline |
| Móvil RTL | El enlace de salto fuera de pantalla creaba overflow horizontal | Se sustituyó por recorte accesible con propiedades lógicas |
| Generadores | Una sincronización futura podía restaurar el contenido incorrecto | El generador original y ambos scripts `sync-web` usan la nueva fuente canónica |

## Archivos y grupos modificados

- Runtime y presentación: `index.html`, `app.js`, `styles.css`, `pwa.js` y
  `service-worker.js`.
- Contrato y datos: `data/portfolio-i18n.json`, `api/v1/i18n/*.json` y
  metadatos de generación de `api/v1/`.
- Rutas y documentos generados: `i18n/*`, `docs/i18n/*`.
- Generación y empaquetado: `scripts/generate-expanded-locales.py`,
  `scripts/build.js`, `scripts/sync-web.ps1`, `scripts/sync-web.sh` y
  `scripts/sync-portfolio.py`.
- Pruebas y CI: `scripts/validate.js`, `scripts/validate-i18n.js`,
  `scripts/functional-i18n-smoke.js`, `package.json` y
  `.github/workflows/ci.yml`.
- Documentación vigente: `README.md`, `CLAUDE.md`, `cv-data-api.md`,
  `CHANGELOG.md`, guías técnicas, móviles, de validación y sus espejos wiki.

No se alteraron hechos profesionales. Los cambios en los JSON generales de la
API se limitan a la fecha de generación y a describir la nueva capacidad i18n.

La validación estructural recorrió los 22 locales, las cuatro vistas, las 16
secciones y todos los enlaces PDF. La prueba funcional utilizó un viewport
móvil de 390 × 844 y verificó cero overflow horizontal, rutas representativas,
RTL en árabe y persa, fallback inválido a español y recarga offline con idioma,
tema y vista persistentes.

## Límite de la validación local

La SPA compartida, el empaquetado web, los scripts de copia y la configuración
`webDir: 'www'` de Capacitor quedaron validados. En este entorno Windows no se
compiló el proyecto iOS ni se realizaron pruebas en hardware físico. La prueba
automatizada cubre la capa funcional que Android/iOS empaquetan; la firma,
instalación y comportamiento del WebView nativo deben confirmarse en sus
toolchains antes de publicar un binario nuevo.
